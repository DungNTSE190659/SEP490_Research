1. Paper Title
English: Beyond AUC: Do Better Knowledge-Tracing Models Make Better Tutors? Evaluating Prediction vs. Exercise-Sequencing Utility across Math and Programming

Target venue: ICIIT 2027 (12th Int. Conf. on Intelligent Information Technology, FPT University HCMC, Mar 2027) — ACM proceedings, indexed by Scopus / Ei Compendex. Upgrade path: Journal of Advances in Information Technology (Scopus).
2. Abstract
Knowledge tracing (KT) underpins the adaptive engines of intelligent tutoring systems, yet models are almost universally ranked by next-step prediction accuracy (AUC/RMSE). Whether such accuracy gains translate into better instructional decisions — which exercise to present next — remains poorly understood, and recent benchmarks show that reported KT accuracy is highly sensitive to preprocessing and can be inflated by label leakage. This paper empirically decouples predictive accuracy from downstream sequencing utility. Using the standardized pyKT and EduData pipelines, we evaluate a representative set of KT models (BKT, DKT, DKVMN, SAKT, AKT) on fully public benchmarks spanning mathematics (ASSISTments2009, Junyi Academy) and programming (Peking Online Judge). For each model we (i) measure prediction quality and (ii) use the model as a student simulator to score simple next-exercise sequencing policies, then analyse the correlation between the two, with robustness checks that acknowledge known limitations of simulator-based evaluation. Our results characterise when — and in which domain — a more accurate KT model actually yields a materially better tutor, offering practical guidance for adaptive-learning engines and a reusable, fully reproducible evaluation protocol.
Keywords: knowledge tracing; adaptive learning; intelligent tutoring systems; instructional sequencing; educational data mining; reproducibility.
3. Research Questions & Contributions
Research questions
RQ1: How much does next-step prediction accuracy (AUC/RMSE) vary across KT models under a standardized, leakage-controlled protocol?
RQ2: Does higher predictive accuracy translate into better next-exercise sequencing utility (via simulator-based offline evaluation)?
RQ3: Does the accuracy–utility relationship differ between the mathematics and programming domains?
Intended contributions
A reproducible, fully public protocol that measures KT models on both prediction and downstream sequencing utility.
An empirical accuracy-vs-utility analysis across math and programming benchmarks.
Practical guidance for choosing the KT model/policy inside an adaptive-learning engine (e.g., AlgoVenture).

5. Datasets & Access
Use only frictionless, directly downloadable datasets as the core (green). Gated or flaky sources (red) are kept optional — do NOT make the project depend on author approval. Verify each link before committing.
Tools that remove the access friction
pyKT (pip install -U pykt-toolkit): NeurIPS-2022 benchmark library; standardized preprocessing for 7+ datasets (incl. POJ programming) and 10+ KT models — the recommended backbone.
EduData (pip install EduData): CLI auto-downloader — 'edudata ls' to list, 'edudata download assistment-2009-2010-skill' / 'edudata download junyi'.
Kaggle: Junyi Academy and Riiid/EdNet mirrors — free with a Kaggle account, no author approval.
Avoid as a hard dependency: CodeWorkout (PSLC DataShop #3458 — account + possible PI approval, site often unresponsive) and FalconCode (HuggingFace gated — request awaits author review). Treat both as optional bonuses only.
6. Baseline Models
Classic: Bayesian Knowledge Tracing (BKT).
Deep: DKT (LSTM), DKVMN (memory network), SAKT & AKT (attention-based); optionally simpleKT as a strong simple baseline.
Implementation: prefer pyKT's built-in model implementations for a fair, standardized comparison; Python + PyTorch.
7. Evaluation Plan
Prediction: AUC, RMSE, ACC under student-level cross-validation and the pyKT standardized split.
Sequencing utility: use each trained KT model as a student simulator; evaluate next-exercise policies by estimated learning gain; compute the accuracy–utility correlation across models.
Generalisation: compare the accuracy–utility pattern across the math datasets and POJ (programming).
Rigour: report statistical significance and effect sizes; include leakage/robustness checks; release code + configs for reproducibility.
8. Honest Notes, Risks & Scope
Positioning: this is an evaluation/analysis paper — it does NOT need to beat state-of-the-art. A negative result (accuracy does not predict utility) is still a publishable finding.
Key risk: simulator-based utility evaluation has known limitations (single-step training vs multi-step inference, cf. AdvKT). Declare this openly and add robustness checks, or reviewers will flag it.
Data caveat: POJ provides response-level (correct/incorrect) coding logs, not rich code structure — so a 'code-structure-aware model' angle is out of scope here and left for future work.
Realistic target: a solid Scopus conference (ICIIT). A strong journal would require deeper experiments and a methodological novelty beyond this scope.
Integrity: declare all AI assistance and third-party tools/datasets with usage evidence, per the RBL submission guideline.
